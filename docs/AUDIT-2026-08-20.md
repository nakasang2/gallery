## 監査方法
決済/Stripe、Three.js/3D、UGC/セキュリティ、法務/グローバル、UI/UX/マーケティングの5観点で、それぞれ専門ペルソナを与えた独立エージェント（Claude Opus）が実コードを読んで指摘を作成。うち **Critical判定の3件と決済まわりの主要High** は、レポート作成者本人（オーケストレーター）が実ファイル（RLSポリシー・トリガー定義・webhook/checkoutのコード）を直接読んで裏取り済み（✅マーク）。さらに5エージェントが読んでいない領域（admin画面のLP編集機能一式など）を狙って追加の見落としスイープを1回実施。

合計 **50件**（Critical 3 / High 17 / Medium 23 / Low 7）。憶測ではなく、すべて具体的なファイル:行番号と失敗シナリオを伴う指摘のみ採用。

## Critical（即対応推奨）

### 1. [Critical] 決済/権限: 有料テーマ・間取りがDB層で守られておらず、直接APIで無料入手できる ✅検証済み
- **対象**: `lib/entitlements.ts:94-100`（判定ロジック）／`supabase/migrations/0001_init.sql:117-121`（`galleries_owner_all`ポリシー）／`lib/galleries.ts:576`（クライアントから直接update）
- **懸念点**: RLSポリシー`galleries_owner_all`は`using (auth.uid() = owner_id)`しか見ておらず、`theme`/`layout`列の値を一切検査しない。`isThemeUnlocked`等のエンタイトルメント判定は`SettingsPanel.tsx`等のUIコンポーネントでのみ呼ばれ、DB書き込み経路には存在しない。ブラウザのコンソールから`supabase.from('galleries').update({theme:'noir', layout:'portrait'}).eq('id', 自分の部屋id)`を実行するだけで、$8のテーマと$5の間取りを無料で入手できる。**同じ脆弱性クラスに対し、`work_cap`（migration 0036）・`slots_included`（0038）・`expo_id`（0050）は既に専用の`before update of <列>`トリガで守られている**（0036のコメントに「definerで書いてしまい実測で気づいた」という過去の教訓あり）。`theme`/`layout`だけがこの防御パターンから漏れている。
- **推奨修正**: `guard_work_cap_raise()`と同型の`before update of theme, layout`トリガを追加し、購入していない値への変更を拒否する。

### 2. [Critical] 3D/信頼性: LPのヒーロー3DにWebGLコンテキスト喪失のハンドリングが皆無 ✅検証済み
- **対象**: `components/landing/HeroCanvas.tsx`（全29行）／`components/landing/HeroScene.tsx:1152-1157`／`app/gallery.css:290`／`app/landing.css:332`
- **懸念点**: `webglcontextlost`リスナーはリポジトリ全体で`components/gallery/GalleryApp.tsx`（本編ギャラリー側）にしか存在しない（grep で確認）。LPの`HeroCanvas`は一度`enabled=true`になったら戻らず、コンテキストロスト時にCSSフォールバック（額装/廊下の代替表示）へ切り替える手段がない。iOS Safariでアプリ切り替え後に戻る等でコンテキストが失われると、**最も流入の多いLPのファーストビューが黒いまま復帰不能**になる。
- **推奨修正**: `GalleryApp.tsx`と同じ`preventDefault()`+Canvas再構築ロジックをHeroCanvasに移植。喪失中は`has-hero3d`クラスを外し、CSSフォールバックを実際に表示させる。

### 3. [Critical] 法務/決済: アカウント削除で購入履歴(purchases)がDB cascadeで消え、プライバシーポリシーの記述と矛盾する ✅検証済み
- **対象**: `supabase/schema.sql:512`（`user_id uuid not null references auth.users(id) on delete cascade`）／`supabase/migrations/0007_delete_account.sql:19`（`delete from auth.users where id = auth.uid()`）／`app/privacy/page.tsx:55`／`app/terms/page.tsx:48`
- **懸念点**: `delete_my_account()`は`auth.users`行を削除し、FKのcascadeで`purchases`の全行が連鎖削除される（0017〜0067のどのmigrationもこのFKを変更していないことを確認済み）。一方でprivacy policy §6は「購入記録は税務・会計上必要な期間、アカウント削除後も保持する」と明記しており、実装がこの約束を守れていない。返金ポリシー（告知前12か月以内は返金）の検証や管理画面の売上集計も遡って狂う。
- **推奨修正**: `purchases.user_id`を`on delete set null`にし、削除RPCで購入行を非個人情報化した形で保持する。自社DB単独で帳簿保存義務を満たす前提かは**要弁護士確認**。

## High

### 4. [High] 決済: 非同期決済手段（コンビニ払い等）の完了イベントを処理しておらず、支払われても永久に付与されない ✅検証済み
- **対象**: `app/api/stripe/webhook/route.ts:55, 59-63`（コメント自身が`checkout.session.async_payment_succeeded`に言及している）
- **懸念点**: `checkout.session.completed`以外は即ack、`payment_status !== 'paid'`も捨てる。`checkout/route.ts:197`の`sessions.create`は`payment_method_types`を指定しておらず、Stripeダッシュボード側の設定次第で非同期手段が提示されうる。その場合の完了通知を受けるハンドラが存在せず、課金だけ成立してコンテンツが付与されない。
- **推奨修正**: `checkout.session.async_payment_succeeded`（付与処理を共通化）と`async_payment_failed`のハンドラを追加。

### 5. [High] 決済: 部屋容量の並行購入で、課金されたのに枠が増えないケースが無検知 ✅検証済み
- **対象**: `supabase/migrations/0031_purchase_currency.sql:63-75`（`record_capacity_purchase`）／`app/api/stripe/webhook/route.ts:161-171`
- **懸念点**: `update ... set work_cap = least(work_cap + p_amount, 15)`はキャップに当たって実際の増分が少なくても、行が更新された事実だけで`'applied'`を返す。webhookは`no_gallery`とRPCエラーしか見ないため、ほぼ同時に2つのリクエストが容量を購入すると、片方は課金されたのに枠が増えない「無検知の課金漏れ」が起きる。
- **推奨修正**: RPCの戻り値に実際の増分(delta)を含め、要求量との差があればログ・返金対象として記録する。

### 6. [High] 決済: 既に所有しているテーマ/Video Passの再購入を事前チェックしておらず、二重課金がリカバリ不能 ✅検証済み
- **対象**: `app/api/checkout/route.ts:82-93`（single_item/video_passの所有チェックが存在しない）／`webhook/route.ts:28-32`（`insertPurchase`が`'duplicate'`を返すだけで`break`）
- **懸念点**: チェックアウト作成時に「既に持っているか」を確認していない。古いタブ・二重クリック・直接POSTで同じ商品を再購入すると、Stripeでは正常に2回課金されるが`purchases`にはUNIQUE制約で2件目が書き込まれず、突き合わせ不能な「台帳に残らない課金」が発生する。
- **推奨修正**: checkout route側で対象アイテムを既に所有していないか確認し、所有済みなら409を返す。

### 7. [High] 3D: 動画作品のVideoTexture/`<video>`要素がdisposeされずメモリに蓄積する
- **対象**: `components/gallery/VideoArt.tsx:29-46, 48-54, 71-84`
- **懸念点**: `videoTex`/`posterTex`が`useMemo`で`art.src`変更ごとに再生成されるが、古いテクスチャを明示的に破棄していない（コメント上はGCに委ねる意図）。`<video>`も`pause()`のみでデコーダは解放されない。作家が動画作品を何度も差し替えると蓄積し、iOS Safariの同時デコーダ数上限に達して以降の動画がフリーズ/黒画面になりうる。売り物のVideo Pass機能に直撃。
- **推奨修正**: 生成を`useEffect`に移し、クリーンアップで`dispose()`と`video.removeAttribute('src'); video.load()`を呼ぶ。

### 8. [High] 3D: 光の焼き込みにタイムアウト/エラー境界がなく、保存ボタンが恒久的に無効化されうる
- **対象**: `components/BakeStatus.tsx:94-104`／`components/gallery/ShadowBakeRunner.tsx:69`／`app/me/page.tsx:3075`
- **懸念点**: `phase`が`'baking'`から抜ける唯一の道が`onFinished`コールバックで、焼き込み用Canvasがコンテキストを取得できない等の理由で一度も呼ばれないと、保存ボタンが「更新中」のまま永久に押せなくなる。リロード以外の脱出路がない。
- **推奨修正**: 進捗が一定時間動かなければタイムアウトで`onFinished({ok:false, reason:'timeout'})`を発火し、error boundaryも追加する。

### 9. [High] 3D: ライトマップ焼き込みの失敗が無検知で、非対応端末の部屋が意図の25%の明るさに固定される
- **対象**: `components/gallery/LightmapBaker.tsx:99-112`／`components/gallery/lightPlan.ts:200`（`POOL_MIX = 0.25`）
- **懸念点**: 必要な拡張（`EXT_color_buffer_half_float`等）が無い環境で3回のリトライ後に諦めるが、ログ・テレメトリが一切ない。来場者には「なんとなく暗い部屋」としか見えず、誰にも報告されず検知できない。
- **推奨修正**: 拡張チェックを事前に行いフォールバック品質に切り替える、または打ち切り時に`POOL_MIX`を引き上げ、`track()`で計測する。

### 10. [High] UGC/法務: モデレーションで非公開にしてもR2上のファイルは公開され続け、DMCAの迅速削除要件を満たさない
- **対象**: `lib/admin.ts:179-185`（`admin_set_gallery_public`のみ）／R2は公開バケット・Edge TTL 1か月
- **懸念点**: 管理者が取れる唯一の措置がギャラリーを404にすることで、通報者が貼った画像URL自体は生き続ける。17 U.S.C. §512(c)(1)(C)の"expeditiously disable access"を満たさない可能性があり、セーフハーバーの前提が崩れる。部屋単位の措置しかないため、合同展示で1点侵害があっても無関係な参加作家が連座する。
- **推奨修正**: `is_admin()`配下でservice-roleにより該当ファイルを`deletePrefix`+CDNキャッシュパージする管理APIと、作品単位の非表示RPCを追加。

### 11. [High] UGC: 通報フォームが匿名・無制限で、管理画面自体をDoSできる
- **対象**: `supabase/migrations/0010_reports.sql:16-19`（`with check (true)`）／`lib/admin.ts:237-255`（`fetchAll('reports')`で全件取得）
- **懸念点**: サインイン不要・レート制限なしで`reports`に書き込めるため、大量投稿すると本物のDMCA通知が埋もれるだけでなく、`/admin`が全件を1000件ずつ取得しようとして開けなくなり、モデレーション機能自体が機能停止する。新規通報の通知（メール等）も無い。
- **推奨修正**: `/report`にサインイン必須化かCAPTCHA、`reports`へのレート制限、`/admin`はopenステータス+直近件数に限定。

### 12. [High] 法務: 利用規約・プライバシーポリシー本文が英語のみで、同意チェックは11言語UIに存在する
- **対象**: `app/terms/page.tsx`／`app/privacy/page.tsx`（全文英語）／`lib/i18n/ja.ts:208`ほか（同意文言は11言語）
- **懸念点**: ドイツ語UIで登録した消費者が読めない言語の約款に同意させられる構造。GDPR12条（明確平易な言語）、EU不公正条項指令5条に抵触しうる。
- **推奨修正**: 少なくともEEA主要言語（ja/de/fr/es/it）へ翻訳するか、返金・UGC権利・免責の要約だけでも全言語で提供する。**要弁護士確認**。

### 13. [High] 法務: EU/UKの法定代理人・単一窓口が未設置
- **対象**: `app/privacy/page.tsx:17-23, 58`
- **懸念点**: 日本の事業者が11言語・EEA向けに役務提供しているが、GDPR27条（EU/UK代理人の指定）、DSA11・12・13条（単一窓口・EU代理人の公表）への対応が確認できない。UGCホスティング事業者としてDSAの小規模事業者免除（19〜28条のみ）の対象外条項に該当しうる。
- **推奨修正**: EU/UK代理人サービスと契約し、privacy policyと`/legal`に氏名・連絡先を明記。**要弁護士確認**。

### 14. [High] 法務: EU/UK消費者に消費税・VAT抜きの価格を表示している
- **対象**: `lib/i18n/en.ts:895`／`lib/i18n/ja.ts:858`（「決済画面で加算されます」）／`app/api/checkout/route.ts:202-206`（`price_data`に`tax_behavior`指定なし）
- **懸念点**: $12等と表示し最後にVATを上乗せする形は、消費者権利指令2011/83/EU 6条(1)(e)（税込総額の事前提示）、価格表示指令98/6/EC・UCPD（drip pricing）に触れる。日本の消費税法63条（総額表示義務）にも「決済画面表示のみ」で足りるか疑義。
- **推奨修正**: Stripe側を`tax_behavior: 'inclusive'`にする、またはEEA/UKアクセスには税込表示を出す。**要弁護士確認**。

### 15. [High] 法務: Google Fontsを同意バナーの外・全訪問者に実行時ロードしており、処理者一覧にも不記載
- **対象**: `app/layout.tsx:74-81`（`<link href="https://fonts.googleapis.com/...">`）／`app/privacy/page.tsx:38-46`（処理者一覧にGoogle Fontsが無い）
- **懸念点**: 同意バナーはGA4のみ制御しており、このリンクはEEA含む全訪問者・同意前から発火し、IPが米国Googleへ渡る。LG München I判決（2022, 3 O 17493/20）が同型実装をGDPR違反と認定。
- **推奨修正**: フォントを自己ホスト化（`next/font`等）。自己ホストするとOFLライセンスの同梱義務が発生するため`OFL.txt`を配置する。

### 16. [High] マーケティング: 作品ページのOGP画像が日本語タイトルで文字化け・欠落する
- **対象**: `app/[handle]/opengraph-image.tsx:36-89`／`app/[handle]/[slug]/opengraph-image.tsx:23-89`
- **懸念点**: `ImageResponse`に`fonts`オプションを渡しておらず、next/ogの既定フォントはLatin系のみ。作家が日本語タイトルで作品ページをSNSにシェアすると、カードのタイトルが空白または文字化けになる。カバー画像に相対パスが来ると500エラーでカード自体が消える経路もあり。
- **推奨修正**: Zen Old Mincho等のsubsetフォントを`fonts`オプションで渡す。カバー画像URLは`lib/seo.ts`の`absoluteMedia()`と同じガードを通す。

### 17. [High] マーケティング: 合同展示ページ(`/expo/{slug}`)にOG画像が1枚もない
- **対象**: `app/expo/[slug]/page.tsx:73`／`app/expo/[slug]/[room]/page.tsx:48`
- **懸念点**: `openGraph.images`が無く`opengraph-image.tsx`も存在しない。$15〜$40という最も単価の高い商品の告知リンクが、画像なしの弱いカードになる。
- **推奨修正**: `app/[handle]/[slug]/opengraph-image.tsx`と同型のものを追加する。

### 18. [High] マーケティング: 決済完了のGA4 purchase相当イベントが存在しない
- **対象**: `app/api/stripe/webhook/route.ts`（外部計測への送信が0行）／`app/me/page.tsx:3486-3491`（`checkout_return`はクライアント側のみ）
- **懸念点**: サーバー側からの計測送信が皆無で、唯一の信号はリダイレクト直後のクライアントイベント。タブを閉じる等で計測漏れが起き、EEA/UKはCookie同意前提でさらに欠測する。Meta Pixelは実装ゼロ。
- **推奨修正**: `success_url`にセッションIDを付与し検証後にGA4 purchaseを送る。webhookからもMeasurement Protocolで送信し取りこぼしを防ぐ。

### 19. [High]（見落としスイープで発見）管理画面: LP画像枠の読み込み失敗が「未設定」と区別されず、次の保存で他の枠が消える
- **対象**: `components/LpImageSlotsEditor.tsx:64`／`lib/siteConfig.ts:108-121`
- **懸念点**: フェッチ失敗時も`normalize(null, count)`で全null扱いになり、エラー表示が一切ない。一時的なネットワークエラー中に管理者が1枠だけ差し替えて保存すると、**他の全枠の設定が本番LPから消える**。
- **推奨修正**: 失敗と空を区別し、エラー時は保存ボタンを無効化する。

### 20. [High]（見落としスイープで発見）管理画面: LP画像のアップロードが「保存」を待たずに本番へ反映される
- **対象**: `components/LpImageSlotsEditor.tsx:82-94`／`lib/cloud.ts:607-613`
- **懸念点**: アップロードは即座に固定オブジェクトキー`{uid}/lp/{slot}.jpg`を上書きするため、site_configの保存前に離脱してもCDNキャッシュが切れた時点で本番LPの画像が差し替わる。「未保存」表示が約束するコミット点が画像そのものには存在しない。
- **推奨修正**: アップロード先キーにnonceを含め（例: `{uid}/lp/{slot}-{ts}.jpg`）、保存操作だけがsite_configの参照先を切り替えるようにする。

## 確認済みで問題なかった主な項目（参考・再確認不要）

- Webhook署名検証（`constructEventAsync`）、Secret未設定時501、検証失敗400 ── 正しく実装
- 決済金額はサーバー側`lib/pricing`のみで決定、クライアントは金額を送れない
- 購入の冪等性（`UNIQUE(user_id, kind, item_key)`）、ゼロ小数点通貨16種の処理 ── 正しい
- アップロードURLのIDOR対策（`auth.uid()`からキーを組み立て、クライアントはパスを名乗れない）、容量の二重締め（実測+予約台帳）
- 管理画面の認可はRLS+`security definer`のRPCが実体で、URL直叩きでは突破できない
- Three.jsの主要コンポーネント（Room/Exhibit/TitleWall/Dust/GalleryScene環境マップ等）のdispose、GLBのDraco圧縮、アップロード画像の1600px丸め、`forceContextLoss()`によるアンマウント時のGPU解放
- Cookie同意（Consent Mode v2、地域デフォルト、gtag.js投入前の設定）
- DMCA通報フォームの法定必須項目（署名・著作物特定・連絡先・宣誓）
- 特定商取引法の表示は電話番号以外すべて`check:price-disclosure`で機械的に担保
- 3Dキャンバスとページスクロール/HUDタップの競合（`touch-action:none`と`inert`で対策済み）
- 作品ページのOGPは動的生成済み（`/expo`系のみ欠落）
